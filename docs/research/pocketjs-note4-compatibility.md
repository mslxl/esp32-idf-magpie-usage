# PocketJS suitability for ZECTRIX NOTE4

**Access date:** 2026-10-23

**Scope:** PocketJS at its current official `main` source revision `e27bff3e96df3c7b3c8263a34f2362b964df04fb` and the ZECTRIX NOTE4 development guide. The companion example in this repository now validates the static 1-bpp path on a physical NOTE4 PCB v1.0.

## Source-backed facts

### PocketJS

- **Runtime and app model.** PocketJS describes apps written in TypeScript using Solid, Vue Vapor, or Octane components. The application runs as a QuickJS guest; a Rust core performs flexbox layout and rendering to a native tree. It explicitly has no DOM, CSS engine, or WebView. [PocketJS README, overview](https://github.com/pocket-nexus/pocketjs/blob/e27bff3e96df3c7b3c8263a34f2362b964df04fb/README.md).
- **ESP-IDF targets and compilation.** The official ESP-IDF host README and `contracts/spec/platforms.ts` target inventory include ESP32-P4 and ESP32-S3 for the host package, QuickJS guest, UI core and RGB565 renderer; the PPA component is P4-only. Native Rust core/renderer archives are built for P4 with `riscv32imafc-unknown-none-elf` and S3 with `xtensa-esp32s3-none-elf`; firmware examples use `idf.py set-target esp32p4` or `esp32s3`, then `idf.py build`. The currently pinned ESP-IDF component manifests require `idf: ">=6.0,<6.2"`, and official CI builds both targets with ESP-IDF 6.0 and 6.1. This is newer than NOTE4's reference-project minimum (5.4); do not assume PocketJS components build on IDF 5.4. [ESP-IDF host README, Components / Build the examples](https://github.com/pocket-nexus/pocketjs/blob/e27bff3e96df3c7b3c8263a34f2362b964df04fb/hosts/esp-idf/README.md); [platform contract inventory](https://github.com/pocket-nexus/pocketjs/blob/e27bff3e96df3c7b3c8263a34f2362b964df04fb/contracts/spec/platforms.ts); [`pocketjs_guest` component manifest, `idf` dependency](https://github.com/pocket-nexus/pocketjs/blob/e27bff3e96df3c7b3c8263a34f2362b964df04fb/hosts/esp-idf/components/pocketjs_guest/idf_component.yml); [ESP-IDF CI matrix](https://github.com/pocket-nexus/pocketjs/blob/e27bff3e96df3c7b3c8263a34f2362b964df04fb/.github/workflows/esp-idf.yml#L42-L50); [ESP-IDF guide, Native archives](https://github.com/pocket-nexus/pocketjs/blob/e27bff3e96df3c7b3c8263a34f2362b964df04fb/docs/ESP_IDF.md#native-archives).
- **Build system and SDK version.** Device integration is via caller-composed ESP-IDF components and C ABI, with example projects built using ESP-IDF `idf.py`. The current component dependency gates require ESP-IDF `>=6.0,<6.2` (and the project CI validates 6.0/6.1), so NOTE4's ESP-IDF 5.4+ reference baseline is not automatically sufficient; first validate the PocketJS integration on an allowed 6.x toolchain or perform a deliberate backport. Source checkout additionally uses Bun for build/package tooling and Rust/Cargo for native archives; a prebuilt `.pocket` app package can be passed to the example without Bun. Rust native archives are either released with components or explicitly source-built. [ESP-IDF host README, Components / Build the examples](https://github.com/pocket-nexus/pocketjs/blob/e27bff3e96df3c7b3c8263a34f2362b964df04fb/hosts/esp-idf/README.md); [ESP-IDF guide, Dependency gates / Native archives](https://github.com/pocket-nexus/pocketjs/blob/e27bff3e96df3c7b3c8263a34f2362b964df04fb/docs/ESP_IDF.md#dependency-gates).
- **Hardware ownership and display path.** The product firmware owns its tasks, input drivers, display buffers, presentation and package storage. The supplied RGB565 renderer supports P4 and S3; P4 may add PPA acceleration, while S3 uses software RGB565 rendering. PocketJS also lists a PocketBook `inkview` host with partial refresh, but that is not an ESP-IDF/SSD2683 backend. The PocketJS smoke examples do not initialize a display panel or read device input. [ESP-IDF host README, opening / Components / Build the examples](https://github.com/pocket-nexus/pocketjs/blob/e27bff3e96df3c7b3c8263a34f2362b964df04fb/hosts/esp-idf/README.md); [ESP-IDF guide, Dependency gates / CI](https://github.com/pocket-nexus/pocketjs/blob/e27bff3e96df3c7b3c8263a34f2362b964df04fb/docs/ESP_IDF.md#dependency-gates); [PocketJS README, Choose your screen](https://github.com/pocket-nexus/pocketjs/blob/e27bff3e96df3c7b3c8263a34f2362b964df04fb/README.md#choose-your-screen).
- **Limitations stated by project.** Rust OOM is fatal. PAK bytes are caller-owned and immutable; the guide documents extra immutable-buffer checks needed for its pinned QuickJS source. The ESP-IDF integration guide reports release validation on P4 and S3 targets (including a Waveshare P4 board and AtomS3R), not NOTE4 hardware. [ESP-IDF host README, Components](https://github.com/pocket-nexus/pocketjs/blob/e27bff3e96df3c7b3c8263a34f2362b964df04fb/hosts/esp-idf/README.md); [ESP-IDF guide, Native archives / Package contract / Hardware release gates](https://github.com/pocket-nexus/pocketjs/blob/e27bff3e96df3c7b3c8263a34f2362b964df04fb/docs/ESP_IDF.md).
- **License.** PocketJS and MicroTS are MIT licensed. The separate Pocket3D license applies to `pocket3d/`, `devices/`, and `engine/pocket3d/`; it adds a title-card condition only for distributed products that draw 3D scenes with Pocket3D. The package-level SPDX expression `(MIT AND LicenseRef-Pocket3D-1.0)` should therefore not be read as imposing that title-card condition on a PocketJS-only 2D app; review the exact shipped code and dependencies. [README, License](https://github.com/pocket-nexus/pocketjs/blob/e27bff3e96df3c7b3c8263a34f2362b964df04fb/README.md#license); [`package.json`, `license` / `files`](https://github.com/pocket-nexus/pocketjs/blob/e27bff3e96df3c7b3c8263a34f2362b964df04fb/package.json#L1-L8); [`pocket3d/LICENSE`](https://github.com/pocket-nexus/pocketjs/blob/e27bff3e96df3c7b3c8263a34f2362b964df04fb/pocket3d/LICENSE).

### ZECTRIX NOTE4

- **Hardware / target.** The guide applies to black-and-white NOTE4 devkit PCB v1.0, with ESP32-S3 N16R8, 16 MB flash, 8 MB PSRAM, and 4.2-inch 400×300 monochrome e-paper controlled by SSD2683. Its reference firmware is not for four-colour NOTE4C; the guide warns not to cross-flash. [NOTE4 guide, applicability warning / Main features / Specifications](https://wiki.zectrix.com/zh/software/note4-development-guide#主要特性).
- **SDK and language/build workflow.** The public reference project is for ESP-IDF 5.4 or later and uses the `idf.py set-target esp32s3`, `idf.py build`, flash/monitor flow; the guide links the official MIT reference project and its Quick Start/Hardware docs. It is a conventional ESP-IDF firmware project, distinct from PocketJS app code written in TypeScript. PocketJS's own component manifests currently require ESP-IDF 6.0–6.1, so the shared ESP32-S3 chip target does not establish SDK-version compatibility. [NOTE4 guide, Software development → ESP-IDF reference project](https://wiki.zectrix.com/zh/software/note4-development-guide#esp-idf-参考项目); [NOTE4 reference project](https://github.com/itopinion/zectrix-note4-epd-demo); [PocketJS component manifest](https://github.com/pocket-nexus/pocketjs/blob/e27bff3e96df3c7b3c8263a34f2362b964df04fb/hosts/esp-idf/components/pocketjs_guest/idf_component.yml#L6-L10).
- **Display and interaction interfaces.** E-paper signals are GPIO6 power enable, 8 BUSY, 9 RESET, 10 DC, 11 CS, 12 SCK and 13 MOSI/SDA. The panel supports 1-bpp full/partial refresh; the linked reference project supports 4-bpp/16-level full-screen grayscale. Buttons are GPIO39, 18 and 0 (active low); the guide also maps I2C SDA/SCL to 47/48, RTC PCF8563 at 0x51, and NT3H NFC at 0x55. Audio codec ES8311 uses I2S signals; Wi-Fi and BLE are listed features. [NOTE4 guide, Main features / Pin mapping subsections](https://wiki.zectrix.com/zh/software/note4-development-guide#引脚映射).
- **Power and constraints.** GPIO17 controls the board’s power latch and battery-powered firmware must maintain its required latch state. Signals are 3.3 V only. SSD2683 does not have a manufacturer-hosted datasheet linked in the guide; ZECTRIX points developers to the schematic and public reference driver. Third-party firmware, partition changes and hardware changes are developer responsibility; keep a full original 16 MB flash backup. [NOTE4 guide, Power and reset / Pin mapping / Official component data / Support boundary](https://wiki.zectrix.com/zh/software/note4-development-guide#电源与复位).
- **Officially cited chip/SDK materials.** The guide links Espressif's ESP32-S3 datasheet, NXP's PCF8563 datasheet, Everest's ES8311 product brief, and the Espressif Component Registry ES8311 component. It explicitly notes no public manufacturer SSD2683 datasheet is offered. [NOTE4 guide, Official component data](https://wiki.zectrix.com/zh/software/note4-development-guide#官方器件资料).

## Compatibility conclusion

**Hardware target match, with a deliberate SDK and display adapter.** PocketJS explicitly provides an ESP-IDF host for ESP32-S3 and an Xtensa-targeted native build, so NOTE4's ESP32-S3 silicon aligns with PocketJS's stated S3 target. PocketJS's current component manifests and CI target ESP-IDF 6.0/6.1, so the proof uses ESP-IDF 6.1 and keeps that SDK as an external installation prerequisite. The ordinary PocketJS S3 UI path uses software RGB565 rendering; its P4-only PPA accelerator is not applicable.

**The significant gap is device integration.** PocketJS assigns panel initialization, framebuffer/display presentation, hardware input drivers and task ownership to the product firmware, and its examples do not implement NOTE4’s SSD2683 or GPIO/I2C/I2S hardware. The committed example supplies the needed static adapter: it renders PocketJS RGB565 strips, converts them to NOTE4’s 400×300 1-bpp framebuffer, preserves the GPIO17 power latch, and calls the pinned driver's full-refresh API. The resulting firmware was flashed to the confirmed NOTE4 device on COM5 after a complete 16 MiB original-flash backup, and the physical panel displayed PocketJS-generated `Hello World`. Partial refresh, animation, input, sleep, audio, I2C, and 4-bpp waveform behavior remain outside this proof.

**License scope.** The MIT license covers PocketJS and MicroTS. The Pocket3D title-card condition applies to distributed products that use Pocket3D to draw 3D scenes; an ordinary PocketJS-only 2D app is documented as exempt. Audit the exact shipped components and dependencies before redistribution.
